# トレーニングの記録

目標は「なるべく少ない画面遷移で、簡単に記録できること」。参考にした筋トレMemo のレビューでは、階層をたどる画面遷移の多さ、アプリを切り替えると最初の画面に戻される、セットを消しにくい、といった不満が多かった。

たたき台（Design キャンバス）: https://claude.ai/artifact/7gjY6NppHkQuSksDehaMuW
※ 記録画面のたたき台は、下の仕様に変わる前のもの。開始シートは「今日はどれをやる？」の版が最新

## 流れ

1. ＋をタップ → 開始シート
2. 「空で始める」（ルーティンは今後）→ 記録画面が開き、すぐに種目の選択が出る
3. 種目を1つ選ぶ → そのまま、その種目の入力ページに進む（選ばずにキャンセルすると、空の種目一覧に残る）
   - 以前は空の種目一覧から「種目を追加」を押す必要があったが、始めた直後にやることは種目を選ぶことしかないので、1段省いた
4. 入力ページの下の「次の種目を追加」→ 種目を選ぶ → 次の入力ページへ（戻ると一覧）
5. 一覧の「完了」→ 保存して終了 / 記録を破棄

## 開始シート

- ルーティンを「最後にやった日からの日数」が長い順に並べ、一番上に「次はこれ」を付ける。各行の「開始」で1タップで始められる
  - 「前回と同じメニュー」を一番上に出す案は却下。全身法でない限り、前回と同じメニューをやることは少ないため
- ルーティン機能が未実装のため、今は空の状態の表示と「空で始める」だけ

## 記録画面は「種目一覧」と「種目ごとの入力ページ」に分ける

一度入力し終えた種目に戻ることはあまりないので、全種目を1画面に並べて入力できる利点が小さい。分けることで次の2つも解決した。

- **種目一覧**: 1種目 = 1行。行を長押しすると、そのままドラッグで並べ替えられる（並べ替え用の画面には切り替えない）。スワイプで削除。各行に記録したセットの要約を表示
  - 1画面に全種目を並べていたときは、SwiftUI の List でセクション（種目）をドラッグできず、並べ替えのために画面を切り替える必要があった。それはユーザーの想像と違った
- **入力ページ**: 1セット = 1行。スワイプでセットを削除し、6秒間「元に戻す」を出す

## 種目の追加は1つずつ

選んだらすぐ入力ページに進むので、「追加」ボタンを押す手間がない。トレーニング前にメニューをまとめて決めたい場合は、ルーティンで対応する。

## 前回の値は自動で入れない

前回の値を勝手に入れると、ユーザーが自分で入力する体験を奪う。入れるかどうかはユーザーが選ぶ。

- 空欄には前回の値を薄いプレースホルダーとして表示する（見えるが、入力はされていない）
- 入力ページ上部の「前回の値を入力」ボタンで、前回と同じセット数まで行を足し、空欄だけを前回の値で埋める（入力済みは上書きしない）
- ±ボタンは、空欄なら前回の値を基準に増減する（重量 2.5kg 刻み、回数 1回刻み）
- 「セットを追加」は、同じトレーニング内の直前のセットの値を引き継ぐ（前回のトレーニングではないので自動入力とは扱わない）

## 完了チェック（✓）はない

前回の値を自動で入れていたときは、「やったセット」と「入っているだけのセット」を見分けるために✓が必要だった。自動で入れなくなったので、**回数が入力されているセット = やったセット**として保存し、空欄のまま残ったセットは保存しない。休憩タイマーを作るときは、何を起点にするかを改めて決める。

## 保存

- 記録中のトレーニング: `@Shared(.activeWorkout)`（ファイル保存）。アプリを閉じても続きから再開できる
- 完了したトレーニング: `@Shared(.workoutHistory)`（新しい順）。回数を入力したセットだけを、終了日時付きで保存する
